# SFT 后的类别集合强化学习

RL 是可选阶段。仓库实现论文中的类别奖励，并提供框架启动配置；原始铁路专用 GRPO/GSPO 脚本和精确 RL 数据集尚未找回。这些配置是重建起点，不是已验证的历史训练重放。

## 数据

使用经过视觉审核并确认缺陷类别的合成图像。NanoBanana 提示词中的目标标签不能直接作为真值。教师文本可用于 SFT；RL 的 `solution` 保存明确的最终类别集合。

```bash
python -m railmind export-rl --records data/synthetic/reviewed.jsonl \
  --image-root outputs/generated --output data/rl/train.jsonl
```

记录包含图像消息、解析后的图像路径，以及含 `anomaly_classes` 的 JSON 字符串 `solution`。默认导出要求 `source=synthetic`、`split=train`、图像哈希匹配且审核通过。真实数据 RL 应作为单独实验，不混入合成数据配置。

## 奖励

- 类别集合完全匹配：`1.0`。
- 预测为真值的严格超集：`0.5`。
- 漏检、无效 JSON、未知类别或最终答案格式错误：`0.0`。

只解析最终 JSON，分析文字中提到的类别不算预测。预测与真值都为空属于完全匹配；负样本上多预测类别也会获得论文的超集奖励。分析精确率时需说明这种偏向多预测的部分奖励。

插件位于 `training/railway_reward.py`，注册名为 `railway_category`。测试覆盖完全匹配、多报、漏报、未知类别和格式错误。

## GRPO 与 GSPO

在独立、兼容的 GPU 环境中安装所选 ms-swift 快照。该源码版本为 `4.0.0.dev0`，不是锁定的 PyPI 稳定版。

```bash
python -m pip install -e .
python -m pip install -e third_party/ms-swift
export NPROC_PER_NODE=4
python -m railmind train rl --recipe configs/rl/grpo.json \
  --model models/merged_sft --dataset data/rl/train.jsonl --output outputs/grpo
python -m railmind train rl --recipe configs/rl/gspo.json \
  --model models/merged_sft --dataset data/rl/train.jsonl --output outputs/gspo
```

两条命令默认只展示参数，加 `--execute` 才执行。论文设置为 3,134 个提示、每提示 16 次生成、1 个 epoch、学习率 1e-6。启动器检查数据量与名义梯度批量；ms-swift 的 rollout/生成批量语义仍需在 GPU 环境核对，算术检查不能证明与论文有效 rollout 批量相同。

**算法说明：**所保留 GSPO 示例采用序列级重要性采样与较窄裁剪，GRPO 采用 token 级重要性采样；没有实现论文文字所述 GSPO“绝对值基线”。仓库明确记录差异，采用框架引擎，不另写未经验证的 RL 优化器。

分别保存 SFT、SFT+GRPO、SFT+GSPO checkpoint，使用相同评测清单。记录奖励分布、格式错误率、完全匹配/超集比例、各类精确率/召回率及输出长度。奖励上涨本身不代表检测效果提升。
