# Class-set reinforcement learning after SFT

[English](../README.md) · [简体中文](zh-CN/06_rl.md)


RL is optional. The release implements the paper's class reward and framework recipes, but the original railway-specific GRPO/GSPO launch scripts and exact RL dataset have not been recovered. Recipes are reconstructed starting points, not verified historical replays.

## Data

Use visually reviewed synthetic images with verified defect classes. NanoBanana target labels are not automatically ground truth. Teacher text supports SFT; RL `solution` stores the explicit final class set.

```bash
python -m railmind export-rl --records data/synthetic/reviewed.jsonl \
  --image-root outputs/generated --output data/rl/train.jsonl
```

Records contain image messages, resolved paths and a JSON-string `solution` with `anomaly_classes`. Export requires `source=synthetic`, `split=train`, matching image hashes and approval. Treat RL on real data as a separate experiment.

## Reward

- Exact class-set match: `1.0`.
- Prediction is a strict superset of ground truth: `0.5`.
- Missing classes, invalid JSON, unknown classes or invalid final format: `0.0`.

Only final JSON is parsed; classes mentioned in analysis prose are not predictions. Two empty sets are an exact match. Extra classes on negatives can still receive the paper's partial superset reward; account for that overprediction incentive when interpreting precision.

The plugin is `training/railway_reward.py`, registered as `railway_category`. Tests cover exact matches, overprediction, omissions, unknown classes and format errors.

## GRPO and GSPO

Install the selected ms-swift snapshot in a separate compatible GPU environment. Its version is `4.0.0.dev0`, not a pinned stable PyPI release.

```bash
python -m pip install -e .
python -m pip install -e third_party/ms-swift
export NPROC_PER_NODE=4
python -m railmind train rl --recipe configs/rl/grpo.json \
  --model models/merged_sft --dataset data/rl/train.jsonl --output outputs/grpo
python -m railmind train rl --recipe configs/rl/gspo.json \
  --model models/merged_sft --dataset data/rl/train.jsonl --output outputs/gspo
```

Both commands preview by default; add `--execute` to run. Paper settings are 3,134 prompts, 16 generations per prompt, 1 epoch and learning rate 1e-6. The launcher checks record counts and nominal gradient batch size. Verify ms-swift rollout/generation-batch semantics on the GPU setup: arithmetic checks do not prove equivalence to the paper's effective rollout batch.

**Algorithm distinction:** the retained GSPO example uses sequence-level importance sampling and narrower clipping, while GRPO uses token-level importance sampling. It does not implement the paper text's GSPO “absolute-value baseline.” The release documents this difference and uses framework engines rather than an unverified custom optimizer.

Save separate SFT, SFT+GRPO and SFT+GSPO checkpoints and evaluate on the same manifest. Track reward distributions, invalid-format rates, exact-match/superset frequencies, per-class precision/recall and output length. Increasing reward alone does not establish better detection.
