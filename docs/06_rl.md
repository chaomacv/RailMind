# Category-Set RL After SFT

RL is optional. The new release implements the manuscript's category reward and provides framework launch recipes, but the original railway-specific GRPO/GSPO script and exact RL dataset were not recovered. These recipes are reconstruction starting points, not verified replay of a historical run.

## Data

Use visually reviewed synthetic images with verified anomaly categories. The intended NanoBanana prompt labels are not sufficient ground truth. Teacher text can be used for SFT, while RL `solution` stores an explicit final category set.

```bash
python -m railmind export-rl --records data/synthetic/reviewed.jsonl \
  --image-root outputs/generated --output data/rl/train.jsonl
```

Records contain image-bearing prompt messages, resolved image paths and `solution`, a JSON string with `anomaly_classes`. The default exporter requires `source=synthetic`, `split=train`, a matching image hash and approved review. Real-data RL is a separate experiment, not silently combined with the synthetic recipe.

## Reward

- Exact category-set match: `1.0`.
- Strict superset of GT: `0.5`.
- Missed GT, invalid JSON, invalid category or malformed final answer: `0.0`.

Only the final JSON answer is parsed. A category mentioned in analysis prose is not a prediction. Empty prediction/empty GT is an exact match; an extra category on a negative image receives the paper's superset reward. Document this conservative overprediction preference when interpreting precision.

The plugin is `training/railway_reward.py`, registered as `railway_category`. Unit tests cover exact, extra, missed, unknown and malformed categories.

## GRPO And GSPO

Install the selected ms-swift snapshot in a compatible, separate environment with its GPU dependencies. It is a development source snapshot (`4.0.0.dev0`), not a pinned stable PyPI release.

```bash
python -m pip install -e .
python -m pip install -e third_party/ms-swift
export NPROC_PER_NODE=4
python -m railmind train rl --recipe configs/rl/grpo.json \
  --model models/merged_sft --dataset data/rl/train.jsonl --output outputs/grpo
python -m railmind train rl --recipe configs/rl/gspo.json \
  --model models/merged_sft --dataset data/rl/train.jsonl --output outputs/gspo
```

Both commands are dry-runs until `--execute` is supplied. Manuscript defaults: 3,134 prompts, 16 generations, 1 epoch, LR 1e-6. The launcher checks dataset count and nominal gradient batch. ms-swift's rollout/generation batch semantics need confirmation in the GPU environment; the arithmetic check alone does not establish the paper's effective rollout batch.

**Algorithm clarification:** the source GSPO example uses sequence-level importance sampling with narrow clipping, while GRPO uses token-level importance sampling. It does not implement the manuscript's description of a GSPO “absolute value baseline”. This discrepancy is documented rather than copied into a new, unverified RL optimizer. Both use the proven framework engine, not handwritten optimization code.

Keep separate SFT, SFT+GRPO and SFT+GSPO checkpoints and identical evaluation manifests. Log reward distributions, malformed-output rates, exact/superset match rates, per-class precision/recall and generation lengths. A reward increase is not itself a detection improvement.
